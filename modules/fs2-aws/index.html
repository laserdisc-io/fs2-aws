fs2-aws

FS2 streaming wrappers for the AWS SDK v2 clients. Each fs2-aws-* module adds a streaming API on top of a pure-aws client, so you can read, write and consume AWS services as back-pressured Streams and Pipes.



These docs are for the 7.x release; the older 6.x docs are here.

How the modules are built

Every AWS service has two layers:

  1. Generated algebra (pure-aws). Each SDK async client becomes a tagless-final algebra, e.g. SqsAsyncClientOp[F]. Every CompletableFuture-returning method becomes an F-returning method, and an interpreter manages the client as a Resource. The algebra is generated from the SDK, so it tracks each SDK release.
  2. Streaming algebra (fs2-aws). A hand-written module wraps the generated algebra and exposes the operations that suit streams, such as a Pipe that publishes a stream of messages or a Stream that reads an object. The module's algebra is named after the service, e.g. S3[F], SQS[F], SNS[F].

The streaming algebra is built with a create factory that takes the generated algebra, e.g. SQS.create[IO](config, sqsOp), so you control the client lifecycle. fs2-aws-kinesis is the exception: it takes the SDK clients for the Kinesis Client Library.

fs2-aws-testkit test doubles for the Kinesis consumer and producer fs2-aws-kinesis

The underlying clients are documented on the pure-aws page, including the interpreters and the clientResource option for passing your own SDK client builder.

Import

Add the module you need. Each module pulls in its pure-* dependency transitively:

libraryDependencies += "io.laserdisc" %% "fs2-aws-s3" % "6.6.0"

Testing

Each streaming module calls a tagless-final algebra from pure-aws, and each of those pure modules publishes a tests jar with a Mock…AsyncClientOp stub. Add the stub as a test dependency and override the calls your code makes. fs2-aws-kinesis is the exception: use fs2-aws-testkit. See each module's page for an example.
